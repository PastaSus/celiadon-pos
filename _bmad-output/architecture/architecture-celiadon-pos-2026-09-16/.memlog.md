- (decision) Layered architecture: routes/ (controllers) -> db.ts (pool) -> PostgreSQL. Client: pages/ -> components/ -> lib/api.ts. No state library - React context for auth only.
- (decision) Auth: bcryptjs for hashing, jsonwebtoken for JWT, middleware in server/middleware/auth.ts. Roles: admin, cashier, manager. Token in localStorage, sent as an Authorization Bearer header - not a cookie (verified against shipped code).
- (decision) New DB tables: users (id, email, password_hash, role, created_at), categories (id, name, created_at), stock_movements (id, product_id, type, quantity, reason, user_id, created_at). Products get category_id FK.
- (decision) Shared types in shared/types.ts imported by both client and server via relative path. No Vite alias needed - relative imports resolve in both tsc and the production build (verified; the alias idea is dropped).
- (decision) Component library in client/src/components/: Modal, Button, Table, Toast, LoadingSpinner, Badge, SearchInput, CartDrawer. All Tailwind, no external UI lib.
- (decision) Recharts for dashboard charts. LineChart (revenue), BarChart (top products), PieChart (payment methods). Date range via native date inputs.
- (decision) pg package for PostgreSQL. Parameterized placeholders ($1, $2, $3) with a params array. Transactions via pool.connect() + client.query() + client.release().
- (decision) Deployment: two independent Vercel projects from one repo (Root Directory server, Root Directory client) plus Neon free tier PostgreSQL. Render was the original plan and is abandoned - the repo ships server/vercel.json and client/vercel.json.
- (constraint) No ORM - raw SQL only. No paid libraries. No external UI component libraries (Material UI, Chakra, etc).
